# Adding a Secret to the People Stack

**First check whether the secret already exists in Secret Manager**
(`gcloud secrets list --project=bens-project-462804`). Secrets owned
elsewhere — currently `grafana-otlp-endpoint`, `grafana-otlp-token` (platform
state, `~/src/infra`) and `google-calendar-client-id`,
`google-calendar-client-secret` (schedule terraform — people reuses
schedule's OAuth client, contacts scope on its own refresh token) — must be
referenced as a `data` source here: add the name to the `for_each` set in
`terraform/secrets.tf` `data "google_secret_manager_secret" "shared"` and
skip steps 2, 3, and 6 below (no value needed anywhere in this repo).

For a NEW secret named `my-secret` (kebab-case) / `MY_SECRET` (env var), 6 places change:

1. **`.env`** — `MY_SECRET=<value>`, and add the line to `scripts/fetch-env.sh`
2. **`terraform/variables.tf`** — `variable "my_secret" { type = string, sensitive = true, default = "" }`
3. **`terraform/secrets.tf`** — `google_secret_manager_secret` + `_version` resources (follow the `people_db_password` pattern — a `random_password` generated in Terraform — unless the value is personal or arrives from an external OAuth flow, in which case follow the `google_contacts_refresh_token` pattern: declare the secret resource only, add the version by hand with `gcloud secrets versions add`)
4. **`terraform/cloud_functions.tf`** (and `terraform/api.tf` if `people-api` needs it too) — `secret_environment_variables` block on whichever CF needs it, plus an accessor binding in `terraform/iam.tf` for that CF's SA
5. **`terraform/terraform.tfvars.example`** (placeholder) and **`terraform/terraform.tfvars`** (real value, gitignored) — only for variable-backed secrets, not `random_password`-generated ones
6. **`.github/workflows/deploy.yml`** (and `deploy-api.yml` if relevant) — `TF_VAR_my_secret: ${{ secrets.TF_VAR_MY_SECRET }}` in the apply step's `env:`, then `gh secret set TF_VAR_MY_SECRET --body "<value>" --repo bdrolet/people`

Then: **terraform-plan** (confirm the new resources), get approval, **terraform-apply**.

## Notes on existing secrets

- **`hubspot-token`** — created by inbox terraform, **imported** into this
  repo's state (`terraform import google_secret_manager_secret.hubspot_token
  projects/bens-project-462804/secrets/hubspot-token`), then inbox runs
  `terraform state rm` on it. Versions are not managed here — rotate with
  `gcloud secrets versions add`.
- **`google-contacts-refresh-token`** — the secret resource is declared here,
  but the value is minted locally with
  `scripts/get_google_contacts_token.py` and added by hand
  (`gcloud secrets versions add google-contacts-refresh-token --data-file=-`)
  — a refresh token is personal and never belongs in `terraform.tfvars` or
  state.
- **`people-db-password`, `people-api-token`, `people-sync-token`** — all
  three are generated by Terraform (`random_password`), not passed in as
  variables. A value that must match across `terraform.tfvars`, a GitHub
  secret, and Secret Manager drifts silently; letting Terraform generate it
  avoids that.
